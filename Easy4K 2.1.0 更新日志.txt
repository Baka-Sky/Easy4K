                        Easy4K 2.1.0 更新日志
                  对比版本：2.0.0（2026-09-19）
════════════════════════════════════════════════════════════════════

发行包：Easy4K_2.1.0.0_x64.msix（x64 / 中文，11.59 GB）
适用平台：Windows 10 1809 及以上 / Windows 11

这是一个较大的功能版本。超分从「一个算法」扩成「五个算法 25 个模型」，
补帧从「NCNN / Offical 两档」改成「五个模型族 14 个版本」，
AudioSR 补上了 NVIDIA CUDA 后端并修掉了三个听感问题。


────────────────────────────────────────────────────────────────────
一、新增功能
────────────────────────────────────────────────────────────────────

【1】超分：5 个算法 / 25 个模型（2.0.0 只有 Real-ESRGAN 一个）

    算法（种类）              模型数   定位
    ────────────────────────  ──────  ────────────────────────────
    Real-ESRGAN                  5    动漫与实拍通吃，速度最快，默认选择
    Real-CUGAN                   9    动漫最强，降噪最狠，老番脏源首选
    RealSR                       2    实拍专用，细节最丰富（仅 4x）
    SRMD                         6    实拍轻量路线，速度快、显存低
    waifu2x                      3    动漫元老，线条干净但较慢

    · 全部走 ncnn + Vulkan，A 卡 / N 卡 / 核显都能用，不需要 CUDA
    · 具体模型：realesr-animevideov3-x2/x3/x4、realesrgan-x4plus、
      realesrgan-x4plus-anime、cugan-se 五档降噪、cugan-pro 三档、
      cugan-nose、realsr-df2k、realsr-df2k-jpeg、srmd-x2/x3/x4、
      srmdnf-x2/x3/x4、waifu2x-cunet / anime / photo

【2】补帧：5 个模型族 / 14 个版本

    种类（模型族）                        版本数   定位
    ────────────────────────────────────  ──────  ──────────────────
    NCNN-RIFE（Vulkan，全显卡通用）        47      最快、显存最省
    RIFE（PyTorch，仅 NVIDIA）              4      实拍通用性最好
    DRBA（PyTorch，仅 NVIDIA）              3      动漫保节奏
    GMFSS（PyTorch，仅 NVIDIA）             3      动漫画质最高
    GIMM-VFI（PyTorch，仅 NVIDIA）          4      实拍/动漫通用

    · RIFE：4.26 / 4.25 / 4.18 / 4.26 heavy
    · DRBA：DRBA_RIFE_v4.26 / DRBA_GMFSS_pg / DRBA_GMFSS_union
    · GMFSS：GMFSS_Fortuna / GMFSS_Fortuna_union / GMFSS 初代
    · GIMM-VFI：-R-P / -F-P / -R / -F
    · 随包内置 PyTorch 运行环境，开箱即用

【3】超分与补帧都改成「两级选择」

    超分：算法 → 模型 → 倍率
    补帧：种类 → 模型

    · 倍率会跟着所选模型自动限制（比如 RealSR 只支持 4x，选中后倍率自动切到 4x）
    · 右下角实时显示该模型的推荐星级与「适合场景」说明

【4】AudioSR 支持 NVIDIA CUDA 加速

    · 后端自动选择：N 卡 → CUDA → DirectML → CPU，逐级尝试，失败才降
    · 精度档（FP16 / FP32）始终跟随用户选择，后端降级不会偷偷改精度
    · 三级后端都起不来才报错退出，不再静默改跑 CPU
    · 实测（P106-100，12 秒音频）：CUDA 106 秒，DirectML 94 秒，
      CUDA 约快 5 倍（每窗 19.3 秒 vs 94 秒）

【5】手动输入目标帧率

    · 除了「按倍率」，现在可以直接填想要的目标帧率，成片 fps 精确等于它
    · 避免按倍率相乘后出现小数帧率

【6】单文件超分

    · 主页可直接选单张图片或单个音频做超分，不用跑完整流水线

【7】涡轮分块模式

    · 大素材按块流水处理，块内超分/补帧/合并并行推进


────────────────────────────────────────────────────────────────────
二、问题修复
────────────────────────────────────────────────────────────────────

■ 音频（AudioSR）

 1. 成品音量比原音明显偏小
    修：推理前记录输入峰值，输出按峰值恢复响度；只在超过 PCM 范围时
    才保留余量并限幅。实测由低约 7.9 dB 改善到接近原音。

 2. 成品有概率出现刺耳的高频噪音（某一声道像"炸了"）
    排查结论：不是低通的问题，而是扩散模型在生成频段内的「窄带幻觉」
    ——15~16kHz 出现一簇离散尖峰，高出本地频谱趋势 4.58 倍（+13.2 dB）；
    另外时长向上取整到窗口整数倍时「末尾补零」，最后一个窗口听到的是
    静音、退化成纯无条件采样，会自由发挥。
    修：
      · 时长补零改为「边缘延拓」，让最后一个窗口始终看到延续的真实音频
      · 新增「高频护栏」：只作用于 8kHz 以上、只改幅度不动相位，
        把超出趋势的窄带尖峰压回去；源信号静音处整体衰减。
        实测尖峰最大衰减 12.1 dB，8kHz 以下总能量变化 -0.0000 dB
        （低频完全不受影响）

 3. NVIDIA 显卡上用不了 / 加载到显存后就崩
    修：随包内置 onnxruntime-gpu + CUDA 12 + cuDNN，新增 CUDA 执行器。
    期间修掉两个具体坑：cuDNN 版本需为 9.1.0.70（9.27 会在 Conv 上报
    CUDNN_STATUS_EXECUTION_FAILED_CUDART）；cuDNN 9 的前端在运行时还会
    自己加载后端库，必须把 capi 目录同时加进 PATH，否则进程直接崩。

 4. 在别的电脑上解压后直接报错起不来
    根因：AudioSR 依赖的 scipy 装在本机用户目录，没进便携包，所以只有
    开发机能跑；另外 2.0.0 的包里 Tools\AudioSR 只有一个脚本，ONNX 模型
    和后端都没带。
    修：模型、onnxruntime 运行时、scipy 全部内置随包分发。

 5. 低通滤波会砍掉高频采样
    修：整条低通链路移除，不再提供也不允许开启。

■ 补帧

 6. 补帧「种类」重启后不恢复，还会覆盖用户配置（本版修复）
    现象：在 PyTorch 轨（RIFE / DRBA / GMFSS / GIMM-VFI）选了模型，
    重启后被悄悄打回 ncnn 模型，而且回落的选中值会把配置里的记录也改掉。
    修：启动时按配置里保存的模型反推所属模型族，正确对齐下拉框。

 7. 重启后复用子集报 Access denied，把已经拷好的子集删了重拷
    修：子集复用加标记文件，重启后直接复用，不再删除重拷。

 8. 去重回填时，重复段的「段尾」被插入了过渡帧（幽灵帧）
    修：回填严格校验，每次合并都会核对最终帧数；
    实测每段 25 帧全纯色、段间硬切，真实运动段逐子帧正常渐变。

 9. 帧去重判定过松，真实运动被误判成重复帧
    修：收紧判定阈值；实测重复帧剔除数量不变（未误伤），真重复帧仍正确识别。

10. 「进行中」页的停止/暂停按钮一直是灰的（本版修复）
    修：主管线与单文件任务都算运行中；单文件模式现在也会切到「进行中」页，
    停止按钮能正常打断。

11. 显存溢出后的「自动降级重试」实际无效

12. 补帧一开始就崩溃（rife-ncnn-vulkan 异常退出）

■ 超分

13. Real-CUGAN 的 models-se 在 3x / 4x 下选中「轻度/中度降噪」会让引擎直接崩
    （0xC0000409）
    根因：models-se 只在 2x 提供了 denoise1x / denoise2x 权重，3x/4x 只有
    conservative / no-denoise / denoise3x。
    修：这两个档位限制在 2x，倍率与模型列表联动，选不出不存在的组合。
    （全量实测 41 组「算法 × 模型 × 倍率」组合，41/41 通过）

■ 界面与安装

14. 安装后桌面 / 开始菜单图标发糊（本版修复）
    根因：资源包里 Square44x44Logo 只有 44 / 88 / targetsize-24 / targetsize-48
    四档，缺 targetsize-256（桌面大图标与高 DPI 取的就是它），系统只能把
    88 的小图放大到 256；同时 AppIcon.ico 只有 256 一帧，标题栏/任务栏
    等尺寸也全是缩放出来的。
    修：按 MSIX 资源规范补齐整套 29 个图标文件 —— AppIcon.ico 做成
    16/20/24/32/40/48/64/96/128/256 十帧；Square44x44Logo 补齐
    scale-100/125/150/200/400 与 targetsize-16/24/32/48/256 的
    unplated + lightunplated 变体；Square150x150Logo、StoreLogo、
    LockScreenLogo 也补齐 scale 变体。并确认资源索引（resources.pri）里
    已包含 TargetSize-256 候选，变体才会被系统真正采用。

15. 高级设置里的小字与插图延迟显示

16. 低主频 CPU 下日志过长时有概率界面死锁

17. 检测不到盘符时启动崩溃


────────────────────────────────────────────────────────────────────
三、本次移除
────────────────────────────────────────────────────────────────────

· Offical（PyTorch 版 RIFE）补帧轨
  由 RIFE / DRBA / GMFSS / GIMM-VFI 四个独立模型族取代。
  旧的「模型种类：NCNN 与 Offical」单选也因此下线。

· AudioSR 低通滤波
  理由见上文「问题修复 · 5」——它会砍掉高频采样。

· 补帧倍率与模型不匹配的组合
  倍率现在由所选模型决定，不再允许手工选出跑不了的组合。


────────────────────────────────────────────────────────────────────
四、已知限制与说明
────────────────────────────────────────────────────────────────────

1. PyTorch 轨补帧（RIFE / DRBA / GMFSS / GIMM-VFI）依赖 CUDA + cupy，
   只有 NVIDIA 显卡可用。在 AMD 显卡或核显上选中这些种类会弹窗提示，
   并自动回退到 NCNN-RIFE。程序启动时如果配置里存的是这些模型，
   也会自动回退，不会还原出一个跑不了的选项。

2. 未收录以下模型，原因如实说明：
   · WAFT —— 需要 torch 2.7 + xformers，且它是光流模型不是端到端插帧，
     要自己写 warp 与融合
   · Prometheus / MNN Tariff —— 未找到任何公开实现，疑为 SVFI 自有模型
   · TensorRT（ONNX）—— 是加速手段不是新算法
   · Anime4K —— 是 mpv 的实时着色器，没法逐帧批处理
   · Compact / SPAN —— 公开权重存在，但需要一套通用 ONNX 推理器

3. 安装包体积 11.59 GB，比 2.0.0 明显增大，原因是补帧的 PyTorch 运行环境
   与 AudioSR 的模型、CUDA 运行时全部内置（开箱即用，不需要联网下载）。
   当前 Tools 目录约 16.6 GB。

4. 安装包未做数字签名。安装方式：开启开发者模式后执行
     Add-AppxPackage -Path Easy4K_2.1.0.0_x64.msix -AllowUnsigned
   或使用 Visual Studio 生成的 Add-AppDevPackage.ps1。
